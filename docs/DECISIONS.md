# Decisions

Each entry: the decision, then the reasoning. Newest at the bottom.

## 1. Node headless rendering uses @napi-rs/canvas

The CLI needs a Canvas2D implementation outside the browser. `@napi-rs/canvas` is a prebuilt Skia binding with no system dependencies (no Cairo, no node-gyp). It matches browser Canvas2D semantics closely, which keeps preview and export frames aligned. It is a Node dependency only; the browser uses its native canvas.

## 2. Text is rendered as paths from bundled fonts

Fonts are parsed by our own TrueType reader (`src/text/ttf.js`) and glyphs become cubic Bezier paths. Reasons: (a) morphing and write-on need outlines, not `fillText`; (b) output does not depend on system fonts, so frames are deterministic across machines; (c) the SVG and PDF exporters get real vector text. Inter (SIL OFL) is the UI and label face; KaTeX's fonts (SIL OFL) set math.

## 3. KaTeX for math layout

KaTeX is vendored as `vendor/katex/katex.mjs` (v0.16.47, MIT). We call its internal `__renderToDomTree` equivalent through `renderToString`-free layout: we build KaTeX's virtual DOM tree and walk it with our own box-metric evaluator to place glyphs from the KaTeX font files. This avoids needing a browser DOM for layout, so Node and the browser produce the same math.

## 4. The 3D engine is our own, not Three.js

We write the 3D engine directly: a small scene graph of meshes and lines, a camera model, and two backends: WebGL2 for interactive preview and a deterministic projector that emits depth-sorted 2D paths for Canvas2D, SVG, and board styles. Reasons: (a) board styles need 3D wireframes as strokes that the hand-drawn transform can wobble, which a Three.js raster pipeline cannot give us; (b) headless Node export has no WebGL, and the projector path renders identically there; (c) one less large dependency to vendor and track. Shaded surfaces in the projector use per-face lighting with painter's order refined by BSP splitting where faces intersect.

## 5. Hershey stroke fonts for handwriting

The Hershey fonts (public domain, via kamalmostafa/hershey-fonts, which redistributes the US NBS data under a permissive notice) ship as `.jhf` files in `vendor/fonts/hershey/`. They are real single-stroke fonts with stroke order, which is what a simulated pen needs. For glyphs only available as outlines (user fonts, KaTeX symbols), a skeleton is derived from the outline.

## 6. Docs site is static HTML generated by our own script

The brief allows VitePress or Astro Starlight. Both pull a large node_modules tree and a framework runtime into a project whose stated principle is "plain web stack, no framework". We generate the docs as static HTML with `tools/build-docs.js`, which reads the JSDoc comments, the cookbook Markdown, and the gallery, and renders each example's output as an embedded PNG. The docs share `styles/tokens.css` with the playground. This is the same outcome (API reference from JSDoc, cookbook, gallery, open-in-playground links) with no framework.

## 7. Code editor is our own textarea-based editor

The playground uses a plain overlay editor: a transparent `<textarea>` over a highlighted `<pre>`, with our own tokenizer for JavaScript and Qubi, completions, and diagnostics from the real Qubi parser. CodeMirror 6 is dozens of packages that would need bundling to vendor. The overlay approach is small, accessible (the textarea is a native control), and good enough for scene-sized files.

## Quantum: `if` conditions are evaluated from their source text

The IR carries a branch condition only as `IfBranch.condText`, so `runCircuit` includes a small evaluator (`src/quantum/condition.js`) for the Qubi operators that make sense on classical bits (comparison, logic words and symbols, bitwise, arithmetic, `name[j]` bit reads, `0b`/`0x` literals). Callers that own the full Qubi expression evaluator can pass `evaluateCondition` to the runner and replace it.

## Quantum: measurement registers and indexed bits

`op.register = "m"` stores a measurement's bits in `m` as an integer (the op's first target is bit 0). `op.register = "c[2]"` writes into register `c` starting at bit 2. Importers use the indexed form to represent `measure q[i] -> c[j]`, and the exporters read it back, so classical bit layout survives round trips.

## Quantum: our own seeded RNG in `src/quantum/rng.js`

There is no `src/core/random.js` yet, so the quantum layer ships a 30-line xoshiro128** seeded through splitmix32. Every simulator takes an `rng` or `seed`, so measurement sampling in tests and renders is reproducible.

## Quantum: conventions for observables and metrics

Pauli strings read like kets, most significant qubit first (`"XZ"` is Z on qubit 0 and X on qubit 1). Fidelity uses the squared convention (|<a|b>|^2, and (Tr sqrt(sqrt(rho) sigma sqrt(rho)))^2 for mixed states). The one-qubit depolarizing channel with parameter p is rho -> (1 - p) rho + p I/2. `fidelityDecay(circuit, model, steps)` repeats the circuit `steps` times and reports <psi_k|rho_k|psi_k> after each repetition.

## Quantum: SortBy and SortOrder meanings for Dirac terms

`state` sorts by basis index, `probability` by |amplitude|^2, `amplitude` by the signed amplitude (real part, then imaginary part, so negative-amplitude marked states group together), and `phase` by the phase in [0, 2 pi). SortOrder flips only the primary key; ties always fall back to ascending basis index so output is stable. HideNegligibles hides terms whose amplitude rounds to zero at DecimalPlaces.

## Quantum: two-qubit decomposition by the magic basis

`decomposeTwoQubit` writes any two-qubit unitary as three CX plus one-qubit U gates: the magic-basis KAK splits it into local factors around exp(i(a XX + b YY + c ZZ)), and that core is the Vatan-Williams three-CX circuit (signs fixed by numerical search and verified by reconstruction in tests). Controlled one-qubit gates use the two-CX A X B X C construction, and multiply controlled ones use Barenco et al. Lemma 7.5 with square roots from `unitaryPath`. The same routines lower gates that a target format cannot spell, in the exporters and in the Qubi text emitter.

## Quantum: importers emit Qubi text with a provisional emitter

`src/quantum/import/emit.js` writes Qubi from the IR until the Qubi module's `toQubiSource` exists; the two should be reconciled then. Choices that need confirming against the parser: multi-wire uncontrolled gates use a bracket register (`SWAP [0,1]`); parameterized gates use the call form `RX(0.25) 0`; angles are piradians when a short decimal is exact, else `deg` or `rad` suffixed; user matrices become `gate NAME { matrix: ... }` blocks; barriers are dropped (Qubi has none); `reset` is rejected by every importer because Qubi cannot express it.

## Quantum: Qiskit input is a JSON schema, not QPY

The Qiskit importer reads `{num_qubits, instructions: [{name, qubits, params, clbits}]}`, which a few lines of Python produce from a QuantumCircuit. Binary QPY is refused with an explanatory error: it is versioned per Qiskit release and embeds Python-side payloads (symengine expressions, custom instructions), so a browser parser could not stay correct.

## Quantum: Cirq qubits map by identity, not endianness

`LineQubit(k)` becomes wire k when all qubits are LineQubits; otherwise qubits are numbered in Cirq's sort order. Cirq prints state vectors with its first qubit as the most significant bit while Qubi puts wire 0 last, but that only changes labels, not which qubit a gate touches. Non-integer exponents map to exact Qubi forms where controls make phase observable (CZ^t is CP(pi t), CX^t is H CP(pi t) H) and to rotations up to global phase for uncontrolled gates.

## Text: font containers accepted, and WOFF2 only where Brotli exists

`src/text/ttf.js` reads TrueType (`glyf`, including composite glyphs) and CFF-flavored OpenType (Type 2 charstrings with subroutines, CID-keyed fonts and `seac` accents), plus the first face of a TTC. WOFF 1.0 is unwrapped with zlib (`node:zlib` in Node, `DecompressionStream('deflate')` in browsers). WOFF 2.0 is decoded in full, including the transformed `glyf`/`loca`/`hmtx` tables, but it needs Brotli: Node has it in `node:zlib`; in a browser we use `DecompressionStream('brotli')` where it exists and otherwise throw an error telling the user to convert the font to TTF, OTF or WOFF. Shipping our own Brotli decoder would mean vendoring its 120 KB static dictionary for a format users can convert once. CFF2 (variable OpenType) is rejected with a clear message. The WOFF2 path is tested against a KaTeX font in both containers and matches outline for outline.

## Text: KaTeX layout is evaluated by our own CSS engine

`src/text/tex.js` takes KaTeX's in-memory HTML tree (`__renderToHTMLTree`) and evaluates the subset of `katex.css` that KaTeX depends on: inline flow, `.vlist` tables positioned with `top` against a `.pstrut`, cell text-align, the `.sizing` table, font-family classes, borders as rules, and absolutely positioned SVGs with viewBox scaling and overflow clipping. Clipping of SVG shapes (radical vinculum, arrow shafts, brace bars) clamps coordinates to the clip box, which is exact for KaTeX's shapes because only straight horizontal bars cross the clip edges. Output is identical in Node and the browser (checked byte for byte). Against real KaTeX HTML in headless Chromium, over 28 formulas and 228 glyphs, the largest glyph-origin error is 0.0023 em (tolerance 0.02 em); `tests/unit/text-katex-chromium.test.js` re-runs the comparison whenever a Chromium binary is present.

## Text: TeX token addressing uses a colored probe render

To know which source token produced each glyph, rule or shape, we render a second copy of the formula in which every glyph-making unit is wrapped in `\textcolor{#nnnnnn}{...}` with a unique color. KaTeX builds color groups as transparent fragments, so atom classes and spacing do not change; the probe must produce the same item sequence as the real render, and each item's color then names its token. Script bases are not wrapped (a colored base loses its italic correction and operator limits); the whole `base^sup_sub` is wrapped and the base inherits that color, with prime glyphs routed to their `'` tokens. If the fine probe fails (for example a user macro with unknown arity), a coarse probe wrapping only top-level units is tried, and failing that items stay unmapped and `mapping` reports `'none'`. We rejected `\htmlData` markers (they need `trust` and change sub/superscript placement) and order-based matching (fractions and op limits emit their parts out of source order). `matchTokens` aligns significant tokens with an LCS, then pairs leftover equal tokens so reordered terms still morph.

## Text: skeleton strokes use the nonzero fill rule by default

The outline skeletonizer in `src/text/skeleton.js` rasterizes with our own scanline fill. It defaults to the nonzero rule, not even-odd: glyph outlines and KaTeX's SVG shapes are defined with nonzero filling, and even-odd leaves holes wherever contours overlap (clamped radical bars, fonts with overlapping contours). Even-odd remains available as `fillRule: 'evenodd'`. After Zhang-Suen thinning the skeleton is traced with m-adjacency (so staircase corners are not junctions), spurs are pruned, straight continuations are joined through junctions, and free ends are extended back to the ink tip that thinning erodes.

## Text: layout coordinates and Knuth-Plass defaults

`layoutText` returns world units with y up and the origin at the top-left of the layout box, so the first baseline is at `-ascender`. Knuth-Plass uses TeX's defaults (line penalty 10, flagged demerits 100, fitness demerits 3000; glue stretch 1/2 and shrink 1/3 of a space) and tries tolerances 2, 10, then unlimited before falling back to first fit. Words wider than the line get break points between characters so no line overflows. Line breaks may follow hyphens; no automatic hyphenation dictionary is shipped.

## Qubi: reading measurement results (`name = MEASURE wires`)

The reference does not say how a program reads a measurement. We add one form: `m = MEASURE (a,b)`, with the same parenthesis rules as `MEASURE` (brackets are rejected). `m` becomes a bitstring whose bit k is the k-th lowest measured wire, so the lowest listed wire is the LSB, matching "LSB is q0". Each measure op carries `register: 'm[k]'` for its bit, the indexed form `src/quantum/run.js` already writes bit by bit (a plain `'m'` there would reset the register on every op). The evaluator has two modes. `trace` (default) has no backend: results are unknown, and an `if` whose condition depends on one becomes an op `{kind: 'if', branches: [{condText, ops}], elseOps}` with every branch traced; variables assigned inside those branches become unknown afterwards, and `error()` inside one is a warning. Loop counts, wires, angles, and stdlib arguments that depend on a measurement are errors in trace mode. `execute` takes a backend `{applyOp(op), measure(wires) -> bits, begin?(numQubits)}` (for example `createBackend` in `src/quantum`) and branches on real outcomes. Why this form: it reuses assignment syntax, adds no keyword, and keeps the IR's `if` op as the only runtime branching construct.

## Qubi: `LOOP <0..4> { }` is a sweep over the iteration count

The reference lists `LOOP <0..4> { }` under sweep brackets, and a sweep bracket is an axis of a parametric sweep. So the loop header is one sweep axis (name `<loop>`, key `<loop>@line:col`) whose values are iteration counts: at the point with value 3 the body runs 3 times. There is no implicit loop variable, because the reference names none; programs that need the index keep their own counter (`i = 0` then `i++` in the body). `evaluate` uses the first value of every axis unless `sweepPoint` says otherwise, and `enumerateSweep` walks the cartesian product, discovering axes as it evaluates so a sweep inside an untaken branch is not multiplied in.

## Qubi: dotted numbers, stepped ranges, and ambiguity

Numbers lex as digit runs and the parser reads dotted chains: 1 part is a value, 2 integer parts a decimal (`0.25`), 3 parts `A.S.E`, and 4 to 6 parts are three values in which adjacent integer pairs form decimals (`0.2.0.1.0.5` is start 0.2, step 0.1, end 0.5). When the split is not unique (`0.5.1.3`) the parser asks for parentheses, as in the reference's own `0.(0.5).3`. `1.5.max` is start 1, step 5; a decimal start must be parenthesized. Ranges and stepped ranges include both ends, and `A..B` counts down when B < A. There is no exponent notation (`1e-3`), so emitters must write plain decimals.

## Qubi: angle syntax details

`RX(0.5) q` is the angle form only when the parenthesis touches the gate name; `RX (0,1)` with a space is a wire list (angle omitted, so pi/2). In `RX q -0.5`, a sign with a space before and none after starts the trailing angle instead of subtracting from the wire. Unit suffixes attach directly (`45deg`, `(pi/4)rad`) and convert to CodeAngleUnit, so they mix with bare numbers. `pi` is the plain constant 3.14159, so with the default piradians `RX 0 pi` is a rotation of pi*pi radians; the reference's rule "bare numbers use CodeAngleUnit" applies to it like any number. Inside matrices, trig functions take radians because matrix entries are plain complex numbers. `U(theta, phi, lambda)` is the standard 3-angle unitary, written out in `src/qubi/ir.js` with the other gate matrices.

## Qubi: qubit count inference and the four wire keywords

`MaxQubits` wins when set. Otherwise the count is the highest wire used + 1, raised to 8 when the program uses `max`, `all`, `visible`, or `visiblemax` (these need a count before any wire is known), and to `VisibleQubits` when that is set. The program is re-evaluated until the count stops changing. `visible` is (0..VisibleQubits-1), `visiblemax` is VisibleQubits-1, `all` is (0..MaxQubits-1), `max` is MaxQubits-1. VisibleQubits defaults to the resolved count and is clamped (with a warning) when larger than MaxQubits. `AutoAdjustVisibleQubits` (default false) only grows the displayed `circuit.visibleQubits`; it does not change what `visible` and `visiblemax` mean, so a program means the same thing whichever way the toggle is set. All defaults are in the JSDoc of `src/qubi/settings.js`. `SortBy` accepts `state`, `probability`, `amplitude`, `phase`, the values the quantum layer defines.

## Qubi: builtins where the reference is terse

`typeof` gives the value type (`int`, `float`, `string`, `bitstring`, `list`, `boolean`, `gate`); `listtype` gives the element type of a list (`list-int`, `list-list-int`, `list-float` for mixed numbers, plain `list` for mixed types) and falls back to `typeof` for non-lists. `len`/`length` count elements (bits for a bitstring, characters for a string). `count(x)` counts set bits of a bitstring or nonzero entries of a list, and `count(x, v)` counts occurrences of v, so `len` and `count` differ on lists. `tolist(bitstring)` lists bits LSB first, so `tolist(b)[q]` is qubit q. Casts cover every listed type; `(int)` truncates toward zero. `round` rounds halves away from zero. Interpolated floats use `DecimalPlaces`, and bitstrings interpolate as digits without `0b`. `true` and `false` are literals (the reference has a `boolean` type but no spelling for its values). Every builtin name may be a variable, with a warning, as the reference asks for `count` and `listtype`.

## Qubi: `//` inside brackets is floor division

The reference says `//` is not a comment inside `()` or `[]` on the same line but does not say what it is. We read it as floor division, the usual meaning of `//` in an expression (`CX [0, 4 // 2]`). A bracket opened on an earlier line does not count, so a trailing comment on a later line of a long list still works.

## Qubi: gates, registers, and SWAPSEQ

Controlled gates need a bracket register; the last entries are targets and the rest are controls, and multi-control stays one op. Any op may carry `controls`: the stdlib emits multi-controlled `RY` for state preparation. SWAP, ISWAP, and SQRTSWAP accept `[a,b]` or `(a,b)` with exactly two wires, since a two-element parallel list has no other sensible meaning for them. `SWAPSEQ wires` reverses the order of the listed wires with SWAPs of mirrored pairs; the evaluator emits those SWAP ops in a group named SWAPSEQ, so simulators only ever see SWAP. Gate names are case-sensitive; `h 0` is an error that suggests `H`, and every unknown name is an error (with a "did you mean" hint within one edit).

## Qubi: functions and gate definitions

`fn`/`function` definitions and `gate` blocks go at the top level and are hoisted, so a call may come first. Modifiers come first: `blackbox fn Box(q) { }`. Inside a function, parameters bind positionally, `arg` is the flat list of every argument (lists and registers spread out) and `argmax` its last index, mirroring `max`; assignments are local and globals stay readable. Every call is a `group` (`kind: 'function'`, `blackbox: true` for `blackbox` and `encapsulate`), and nested calls link to their caller through `group.parent`. A `sequence:` is one statement on the line or a `{ ... }` block; its wire k is the k-th wire of the call, and `max` inside it is the gate's last qubit. Without `qubits:` a sequence gate takes all given wires. A matrix acts with targets[0] as the least significant bit and must match `qubits:`; a non-unitary matrix is a warning, not an error, so teaching examples of invalid gates still draw.

## Qubi: annotations, labels, and imports

`ANNOTATE` stands alone and `ENDANNOTATE "id"` closes the region and names it (the reference shows the id only there); regions nest and must close in the same block. `LABEL wires "text"` records its position as the index of the next op. `#import` and `#include` are aliases (the reference lists them together); the file comes from the `resolveImport(path)` option, nesting is limited to 20, a file importing one of its own ancestors is a cycle error, and importing the same file twice through different parents is allowed.

## Qubi: standard library forms

Signatures and circuits are in `docs/qubi-stdlib.md`. Choices the reference leaves open: StatePreparation values are probabilities and whatever is left of 1 goes to the all-zero state (so `StatePreparation(0b101, 0.4)` is 0.4 on 101 and 0.6 on 000); Teleport uses deferred measurement (quantum-controlled corrections) so it runs without classical feed-forward; BV uses a phase oracle, which needs no ancilla; Shor supports N = 15 with multiplication as controlled SWAP rotations plus controlled X for the negative residues; QPE takes the angle of P in CodeAngleUnit; SwapTest's `"similar"` prepares RY(0.4 pi) and RY(0.5 pi) states. Grover defaults to round(pi/(4 asin(sqrt(M/N))) - 1/2) iterations rather than round(pi/4 sqrt(N/M)): the two agree for `Grover(0b110)` and for large N, but the latter gives 2 iterations for N = 4, which lands back on probability 1/4.

## Qubi: scheduling semantics

An op occupies the vertical span from its lowest to its highest wire, controls included, and ops in one column never share span. `never` gives one op per column; `same_line` adds an op to the last column when it fits and otherwise opens a new one; `same_gate_continuous` also requires the same gate name; `same_gate`/`sameType` may place an op in any later column whose ops share its name, as long as it stays after every op it overlaps; `always` is as-soon-as-possible packing; `compressed` is `always` plus merging consecutive loop iterations whose wire sets are disjoint. Loop starts and ends and ANNOTATE regions are boundaries ops never cross, and iteration boundaries hold in every mode but `compressed`, so loop brackets and annotation boxes always enclose whole columns. The schedule reports loop, annotation, group, and label positions in column coordinates.

## Qubi: `toQubiSource` output

The emitter writes `#settings` for the sizes and CodeAngleUnit, gate blocks for user matrices, then one statement per op: piradians when the value is exact to 12 digits, otherwise a `rad` suffix, and never exponent notation. Ops without a Qubi spelling become exact equivalents: controlled RX/RY/RZ become R(theta/2), CZ or CX, R(-theta/2), CZ or CX; controlled S/T/SDG/TDG become CP; controlled H, U, ISWAP, SQRTSWAP, and controlled user gates become a user matrix gate over targets then controls. `if` ops have no flat form and are rejected. The importers' provisional emitter (`src/quantum/import/emit.js`) can switch to this one: the forms it guessed (bracket registers for SWAP, `RX(0.25) 0`, `deg`/`rad` suffixes, gate blocks) are all accepted by the parser.
